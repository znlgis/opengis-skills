# 生产与校验流水线（十一步）

> 本文件是 [../SKILL.md](../SKILL.md) 的参考拆分：十一步流水线的完整职责、脚本执行顺序、关键依赖与门禁矩阵。
> 脚本资产位于仓库 `scripts/` 目录：共用库 `common.py`、入口配置 `config.example.json`、阶段脚本 `01_extract.py` … `09_verify_deliverables.py`（共 12 个脚本）。**语义步骤号与脚本前缀并非一一对应**——如 03b 对应第 4 步、06 对应第 6 步、09 对应第 10+11 两步——映射见 §1 总览、执行顺序见 §2。
> 文中数字均为多图实测值/区间，执行时以实际图纸实测为准。

## 1. 十一步总览

| # | 阶段 | 一句话职责 |
|---|---|---|
| 1 | 矢量提取 + 分层 | `fitz.get_drawings()` 按 **OCG 语义优先 + 颜色兜底** 归六层，落盘基础 SVG 与 glyph 签名 |
| 2 | 视图聚类归属 | outline+dimension+centerline 空间聚类（排除 thin）→ `data-view` 分组与 bbox |
| 3 | 跨图字形字典 | 模板聚类（03）+ 自监督解码（03c）+ 视觉逐行对账（03d）→ 跨图合并字典 |
| 4 | 文本恢复 | 按视图 bbox 高清竖正裁切识读 → 恢复 `<text>` 与 dim-id 绑定 |
| 5 | 配准 | 逐视图定尺度 / 旋转 / 平移 → crosswalk 的 tx/ty + `self_check` |
| 6 | SVG 生成 | 按六层 + 视图分组生成增强版 SVG（骨）——`data-*` 属性、`<text>` 绑定、弧参数旁注、metadata 镜像 |
| 7 | MD 增补 | 补 ID / 语义注解段 / crosswalk 字段 → 重建六层 MD |
| 8 | 三方互校 | MD 重绘 ⇄ SVG 叠合、绿层值集合 ⇄ dims、BOM ⇄ 气球 |
| 9 | LLM 验收 | 数据驱动题库 → 盲测子代理只读交付物作答 → 准确率门禁 |
| 10 | 独立审计 | 不复用生成器判定，从磁盘交付物 + 源 PDF 重算方案条款（`spec_audit`/`final_audit` 探针，不在 `scripts/` 内） |
| 11 | 交付六件套 | 目录清单齐套 + 命名规则 + 报告级核验（`09_verify_deliverables.py` 产出门禁汇总与每图修正单） |

## 2. 脚本执行顺序、幂等与覆写防护

顺序**有依赖**，照旧顺序跑会得到零标签字典：

```
01 → 02 → 03(--all / --contact-sheets / --label-sheets) → 03c → 03d(渲染 / 转录 / --apply / --promote)
   → 03b → 05 → 06 → 04 → 07 → 08 → 09
```

- **`03b` 必须在 `03c`、`03d` 之后**（它读 `glyph_labels.json`）；旧顺序把 `03b` 排在 `03c` 前且漏掉 `03d`。
- **`03c` 与 `03d` 共写 `glyph_labels.json`**：各自**只覆写自己来源的标签、保留对方的标签与 meta 审计键**；否则按顺序重跑 `03c` 会把 `03d` 已采信的标签清回 0。标签的真实出处以标签自带的 `source` 字段为准（`meta.source` 是继承键、不代表写入顺序）。
- **glyph sid 由 `01` 落盘**（`work/glyph_templates.json`），`03` 只读不重算 → 任何对签名函数的修改都必须**从 `01` 起**重跑整链，只跑 `03` 及其后续会让修改**静默失效**。
- **`templates.json` 与接触表只能由 `--contact-sheets` 产出**（`--all` 不更新它），漏跑会让字典停在旧 sid 上；签名口径变化后还须幂等清理孤儿贴片，否则 `templates/*.png` 数与 `templates.json` 不符、齐套门禁误判。
- **`02` 必须在 `01` 之后重跑**（骨架集合依赖 glyph 标记），漏跑得到过期 `views.json`。
- 所有脚本**无状态、可重复执行**；源 PDF **只读不修改**（可用 mtime 早于交付物自证）。
- 环境侧：全链固定 PyMuPDF + PIL、`scale=2.0`，版本由 `07` 在测量当时写入 `validate.json`、汇总报告**读回而非另行探测**（保证与交付物同源）。
- **中文字体**：`config.example.json` 的 `fonts.cjk` 默认 `C:/Windows/Fonts/simhei.ttf` 是 **Windows 默认路径**，其它平台须改为本机中文字体路径（`03d_vision_read.py` 加载失败时会回退默认位图字体，不致命但行格图标签可能缺字）。

## 3. 各步职责

### 步骤 1 — 矢量提取 + 分层

- `fitz.get_drawings()` 按层归六层 → 基础 SVG。
- **分层口径是 OCG 语义优先 + 颜色兜底**：先按 OCG 名归层，颜色只在 OCG 不可用时兜底；**颜色→层硬映射对部分图失效**（实测某图绿色落粗实线 936/1044=90%、另一图洋红双点划线 15703、第三图红 2444 + 黄落通用层「0」1451）。
- **纠偏只在主色占比 >50% 时触发**，且须逐图落盘 `meta.triggers`（四层 bool）+ 每图 `_修正单.md` 输出「分层审计表」（OCG×color 交叉计数 / 主色占比 / 是否触发 / 逐层差值）。否则基线图会被静默改层。
- **title-block 靠 OCG `layer==PDM_Title` 独立成层**；黄色既含 thin（细轮廓）又含标题栏，只靠颜色无法拆。六层合规前提是 title-block 独立成层，否则退化为五层不合规。
- 分层前先剔除整页纯白背景矩形（color=None 的 f 类型图元，实测各图恰 1 个）。
- 注意 `drawing 元素数` 与 `kept/path 数` 是两个口径（各差 1，即整页白底矩形）；计数链须逐一对账 `drawings→bg→kept→SVG path→MD prim_ids`。

### 步骤 2 — 视图聚类归属

- outline+dimension+centerline 三层做空间连通聚类（**必须排除 thin 层**——图框/标题栏线横跨全页会把所有视图串成单簇）；聚类 eps≈25pt（bbox 扩展相交并查集）；与 MD 布局表（r/c 或方位语义）互认，产出 `data-view` 分组与 bbox；详图密集区粘连时人工指定 bbox（`views_override.json`，可选输入、不是交付物）。
- **视图数是聚类的输出、不是可预设的目标**：实测多图视图数区间约 **[8, 26]**，基线图的 26 与基线 27 差 1，且 `MIN_SEED` 全区间扫描（1→416）可得的视图数集合**不含 26/27** → 该偏差不可调参弥合，源于聚类机制本身。
- 「投影间隙切分过合并簇」已实测、**未采纳**（不是漏做）：递归切分使多图一致过分裂、按原样口径扫遍判据只能得 13–16，两者都比现行值离基线更远；且该步依赖的「过合并巨簇」在骨架口径下无对象可切。处理原则：按「记录并解释」登记差异，**不为对齐数字而改机制**。

### 步骤 3 — 跨图字形字典

无文字层 PDF 的尺寸数字/标题栏全是 glyph 轮廓路径，**不先建字典就无法把轮廓还原成字符**，步骤 4 与绿层绑定都无输入。三步：

- **3-1 模板聚类（03）**：`01` 提取时对每个字形算签名并落盘 `work/glyph_templates.json`（**sid 由 `01` 定，下游只读不重算**）；`03 --contact-sheets` 跨多图合并去重 → `output/_glyph_dict/templates/*.png`（逐模板 4× 高清贴片）+ `contact_sheet_*.png` + `templates.json`；`03 --label-sheets` 产出大格标注表。实测合并后模板 1010、实例 11043、标注表覆盖实例 49.8%。**签名口径已偏离原文、且原式被数据否证**：原文「32×32 归一栅格化取位图哈希」同探针口径下得 2399 sid / 13 个已知字符碎成 109 sid / 1 处同 sid 多字符冲突；改用的**量化矢量点集签名**得 1012 sid / 零冲突（CAD 矢量无采样噪声，同字符同字号点集 bit-exact，栅格化反而引入量化误差）。
- **3-2 自监督解码（03c）**：两条明文源（几何尺寸线长度反演 / 图号 crib）**实测均不成立**，故本阶段标签 0。**crib 只作佐证，与 crib 冲突者不入字典**；否则等于向 MD/SVG 注入虚构文本。
- **3-3 视觉逐行对账（03d）**：渲染 tb/notes 两区的行格图，交独立只读代理逐张转录（**必须按分区嵌套** `{"zones":{"tb":{…},"notes":{…}}}`，因 row_id 在各分区独立编号会撞号）→ 过**双闸门**（见下）→ 双过才派生标签、`--apply` 落 `vision_read.json`、`--promote` 跨图汇总到 `glyph_labels.json`。无证据的字符一律 UNK 入 MD §6 不清项。

**视觉识读双闸门**（只有双过才可入字典）：

1. **第一道闸门（图号真值）**：用 PDF 文件名作图号真值，标题栏**单行**转录与图名的最长公共连续子串 ≥ 阈值（不用全区拼接以免假阳）。未过 → **整图不采信**（实测拒两图，丢弃 24+9 个派生 sid）。
2. **第二道闸门（转录字符数核对）**：转录非空白字符数 == 该行字符位数，容差 0。

转录成功率按分区高度偏斜（实测 notes 235/294、tb 35/234）；描述通道在小字高汉字格上会虚构无工程语义串，靠闸门拦下。

### 步骤 4 — 文本恢复

- 整页渲染（≈144DPI）定位后，按视图 bbox **高清竖正紧裁切**（`page.set_rotation(270)` 回正、单边≈1800px）再交视觉多模态模型识读——**低分辨率/未回正会幻觉**；绿层掩码裁切作交叉核对；MD 已有值为先验，产出 `<text>` 与 dim-id 绑定。
- **竖排归一化坐标必须用 `(x,y) → (1−y, x)`**；旧式 `(y, 1−x)` 缺平移校正、两式 y 值相差一个随长宽比变化的常量平移，只在 w/h=0.5 时偶然重合 → 同一字符的正立态与躺倒态**永不同 sid**。写错是**静默降质**（不报错）：实测模板数虚增 1010→1031、竖排已解文本行 129→1、`vert` 绑定尺寸 7→0、SVG `transform="rotate(90 …)"` 分支成死代码。修正后同 sid 兼有两种朝向的模板 4→52、全部图盲测升到 47/47。
- **三条实测约束**：① `zone=notes` ≠ 技术要求——改为「汉字数≥2 的成句行」才入 §5，被排除的行数与样例计入 §6；② §5 为空须用不依赖字典的几何判据自证（`len(items)>9` 数字形判汉字，必要非充分）；③ notes 专切图只裁最大注释簇，逐字核对须回原页裁切。
- 文本恢复来源优先级：MD 已有值 > 绿层 300DPI 裁切复读 > glyph OCR（不推荐，细线 glyph 易碎）；恢复后与绿层值集合做集合核对。

### 步骤 5 — 配准

- 逐视图定尺度（比例来源三档：`read` 识读 / `inferred` 几何反推+score / `fallback` 默认未验证，写入 `scale_source`）/旋转后，用锚点直接求平移得 tx/ty；CAD 矢量无采样噪声、无需 RANSAC；每视图写 `self_check`（原点映射到 bbox 角点）。
- **比例来源三档分级**：实测多图 **`read` 档全为 0**（标题栏比例字段是小字高汉字/符号格，落在能力边界外）；`inferred` 而 `score=0` 者应**直接归 `fallback`**（或加第四档名 `unverified`），档名单独可读——`score=0` 仍叫 `inferred` 会被读作「已推断」。inferred score=0 或 fallback 的 mm 值仅供参考并入 unclear。
- **V00 整页图框区比例用 `frame_scale()` 页面几何自证为 1:1**，不能靠打分：bbox 两轴均覆盖页面 ≥90% 且 den=1 时，W_mm/H_mm 落在由页面 pt 反查出的 ISO 纸型幅面 ±25mm 内 → 判 1:1、`scale_verified=true`、`scale_evidence=page-geometry`，不入 unclear；自证不通过则退回打分（宁缺勿臆）。

### 步骤 6 — SVG 生成

- 读 prims/views/crosswalk（+ text 可选），按六层 + 视图分组生成增强版 SVG（骨）：每 path 带 `data-prim`/`data-prim-id`/`data-ocg`/`data-color`，视图分组 `data-view`，弧/圆/长圆 `data-params` 旁注，已绑定尺寸 `<text data-dim-id data-value>`，metadata CDATA 同源镜像（标题栏/技术要求/视图/crosswalk 摘要）。
- 门禁：SVG path 数 == kept（计数对账链 drawings→kept→SVG path）；六层 `<g data-layer>` 齐全（空层也输出 `data-empty` 空组）；无 UNASSIGNED data-view；metadata 同源镜像；占位符 `?` 不冒充内容。结构与四项增强详见 [svg-spec.md](svg-spec.md)。

### 步骤 7 — MD 增补

- 在现有六层 JSON 上补 ID、语义注解段、crosswalk 字段 → 重建 MD。
- **三条硬约束**（详见 [md-spec.md](md-spec.md)）：① 单文件 ≤80000 字符；② 总量类问题必须有明文句子可逐字核对；③ §3 给 prim-id 区间 + 计数（区间求和 == kept、逐行「末号−首号+1==计数」自洽）。

### 步骤 8 — 三方互校

- MD 重绘 ⇄ SVG 叠合（几何差集）；绿层尺寸值集合 ⇄ MD dims；BOM ⇄ 气球；差异出修正单、人工仲裁后回写。
- **叠合须用容差度量**：0.12pt 发丝线被 fitz 渲为浅灰抗锯齿、PIL 画为纯黑 1px → 严格像素 IoU 假性偏低（实测仅 0.44–0.46）。改 **2px 膨胀 + recall/precision/F1**，门禁 **recall≥0.99**（实测 0.997/0.9998）；补弧/圆拟合残差门禁 rms≤0.1pt；载体一致性（SVG `<text>` 的 (dim-id,data-value) 集合 == MD 绑定 dims 集合，须 True）。
- **precision 不可当门禁**：重绘把线宽取为 `max(1, round(stroke-width×scale))` 的整像素硬边描边，而源图由 PyMuPDF 抗锯齿渲染、墨迹阈值只收极暗像素 → 细线在源图达不到阈值、在重绘图却是满宽硬边，实测 precision 仅 0.747–0.858、多画 71108 px。这是测量口径的不对称，不是交付物多画图元。
- **绿层绑定率非门禁**：识读尺寸值能唯一绑定到绿层等长尺寸线/等径圆的比例仅 41–43%（全自动流水线复跑只得 0.1408）——上限是**字典标签覆盖率**（实测 31/1010 个模板有标签），不是定位算法。未绑定值只入 MD §6 不清项、**不写入 SVG `<text>`**（避免臆造定位）。要提升绑定率须先提升字典标签覆盖率，调定位算法无效。
- 绑定自洽性必须落盘命中判据实际比较的量（`matched_pt`/`match_delta_pt`，而非 `len_pt`——后者对圆弧/长圆是弧长，与直径/半径本不可比）；同一尺寸线被多文本命中时**全部撤绑**入 §6。

### 步骤 9 — LLM 验收

- 数据驱动生成题库（每图 ≥20 题、覆盖五类，实测落到每图 **47 题**）→ 先 `self_check`（answer_keys 均出现在 MD，记 md_verifiable，须 100%）→ 派**盲测子代理仅读交付物 MD/SVG 作答**（不得看参考答案/外部知识）→ 自动判分：answer_keys 全部命中 AND answer_keys_any 任一命中；剥编号前缀（`^\d+[\.、\)]`）防「第4条:」vs「4.」假阳；准确率 ≥95% 方交付（实测全部图 blind 47/47=100%）。
- **四条实测纪律**：① 答案键必须有判别力、禁裸整数（裸整数会被表格行号 `|9|` 假命中）；② 题面必须排除定义上恒最大的候选（V00 按定义图元最多，问「哪个视图图元最多」必中 V00，题面显式排除）；③ 盲测多轮幂等合并、来源可追溯（每轮写新文件 `qa_blind_new*.json` 而非改旧答卷）；④ 不为凑满分喂答案、也不改判分键——只有答案键因上游变更失效时才重答，且记录轮次与理由。

### 步骤 10 — 独立审计（原方案缺失，新增）

前八步的校验都由**生成器自己**判定，存在「生成器说自己通过」的结构性风险。必须另有**不复用生成器判定**的审计，直接从磁盘交付物与**源 PDF** 重算方案条款：

- **`spec_audit`**：逐条重算方案的明文要求（环境版本、页面几何用 `fitz` 直读、分层纠偏明文实测数、MD prim-id 区间自洽、`regions/` 四类齐备、SVG 结构与属性覆盖率、目录清单、命名规则、判分归一化口径、源 PDF 只读），本轮 84 项全过。
- **`final_audit`**：独立重写正则重算逐图硬指标与门禁矩阵，本轮 21 项 × 多图 + 报告级 0 失败格。
- **两条纪律**：① 审计判据必须**先 dump 实际结构再写**（本轮因按假设写判据踩了 6 次：颜色键名是 `c` 不是 `color`、原生旋转值在 `page_rotation_src`、SVG `<g>` 的 data-semantic 排在 data-layer 之后、`self_check` 用 U+2192、`regions` 文件名无前导下划线、`meta.triggers` 恒含四键故 `bool(dict)` 恒 True）；② 审计发现的 FAIL 必须**先定性**（交付物缺陷 还是 审计口径错）再动手。

## 4. 门禁矩阵：硬门禁 vs 基线对账

先分清两类判定（决策 D2），两者不可混在同一张表：把「基线数字对不上」误读为「门禁未过」，会引发为凑数字而改机制。

| 类别 | 含义 | 项 | 不达标时的动作 |
|---|---|---|---|
| **硬门禁** | 交付物的自洽性与合规性，**必须全过**，与任何参照实现无关 | 计数链四相等、六层齐全（含独立 title-block）、无 `UNASSIGNED`、recall≥0.99、rms≤0.1pt、载体一致性（SVG text 集合==MD dims 集合）、`self_check` 全过、QA≥20 题、五类齐全、QA 自检 100%、盲测≥95%、MD≤80000 字符 | **回相应阶段修正后重跑**，不得放行 |
| **基线对账** | 与早先记录的参照数值比较，**只记录并解释** | 逐层图元数、视图数、绑定率、recall/rms 的具体数值 | 写清机制差异与不可复现原因；**禁止为对齐数字而调参或加机制** |

实测：多图 × 12 项硬门禁全绿；基线对账有 **4 项不可复现**（视图数、弧/圆 rms、绿层绑定率、recall），逐项定性为「实现路径与参照实现不同」，均先取证、确认不可调参弥合后按 D2 记录并解释。
